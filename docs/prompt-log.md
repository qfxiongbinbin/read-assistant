# Prompt 版本记录

改动 `src/lib/prompt.ts` 时必须在这里追加一条，并注明评测结果。

## v3 — 2026-09-18（当前）

- 文件：`src/lib/prompt.ts`（新增 `translateSystemPrompt` / `buildTranslateMessages`）
- 用途：划词翻译，**独立于简化主流程**，单独缓存（`ra:t:`），不受 CEFR 档位影响
- 先说清楚：这里的「翻译」不是译成中文，而是把单词或短语**用最简单的外语重说一遍**；零中文硬约束不变

### 约束

1. 只输出英语，绝不译成中文或其他语言
2. 保留原意与全部事实，不增加输入里没有的信息
3. 只用最高频 1000 词；专有名词、产品名与数字原样保留
4. `plainWords`：输入里最难的 1~4 项。`term` 必须原样抄自输入，`simple` 是最多 3 词的最简单说法
5. `plainSentence`：1~3 句，每句 4~14 词；**保留输入的每一个要点**，是换一种说法而不是说得更短
6. **不得复用输入里的难词**——换一种说法才是这个动作存在的意义

### 输入准入（不在 prompt 里，在 `availableActions`）

这个 prompt 只接受 **≤ 40 词**的输入。理由是硬约束：输出预算是 3 句 × 14 词 ≈ 42 词，超过就必须压缩，而 `verifyTranslation` **没有任何规则能检测信息丢失**。所以上限做成结构性约束，前端（胶囊 / tab）与后端守卫共用 `selection.ts` 的 `availableActions()` 一处判定，prompt 里也就不再需要"只保留主要意思"这种主动降标准的措辞。

### 输出与校验

```json
{"plainWords": [{"term": "...", "simple": "..."}], "plainSentence": "..."}
```

校验器 `verifyTranslation`（`src/lib/verify.ts`）：

| 规则 | 阈值 |
|---|---|
| 出现 CJK 字符 | 直接判废（零中文不变） |
| 句数 | <= 3 |
| 平均句长 / 最长句 | <= 16 / <= 25 词 |
| 句中难词 | <= 1 个（原文专有名词豁免） |
| 输入 <= 6 词时复用输入的难词 | 直接判废（单词/短语必须换说法） |
| 输出难度高于输入 | 判废（+5% 容差） |
| 原文中的数字 | 必须保留 |
| `term` 不在输入里 | 判废（按词干宽松比对，容忍词形变化） |
| `simple` 不够常见 | 判废（两个都不常见的词不算替换） |
| 输入有难词但 `plainWords` 为空 | 判废 |

### 评测基线

`npm run selftest`：77 项通过（其中划词翻译 16 项 + 动作准入 10 项）。

### 待观察

- [ ] 「简单词」是否真的比原词更容易，会不会换了个同样难的词继续绕
- [ ] 40 词上限在真实阅读里够不够用，会不会频繁挡住"一句话"级别的选区
- [ ] 上限内是否真的做到了"保留每一个要点"（校验器测不到，需要人工抽样）
- [ ] `plainWords` 是否覆盖了输入里真正难的词，有没有漏掉关键项

## v2 — 2026-09-14

- 文件：`src/lib/prompt.ts`（新增 `explainSystemPrompt` / `buildExplainMessages`）
- 用途：下钻解释，**独立于简化主流程**，单独缓存（`ra:e:`）

### 约束

1. 只用最高频 1000 词
2. 一句话，4~12 词
3. **不得使用被解释的词本身或其任何变形**
4. 多义词只解释「给定句子里的那个义项」（会把上下文一起发给模型）
5. 最多 3 个同义词，优先更简单的词

### 输出与校验

```json
{"explanation": "...", "synonyms": ["...", "..."]}
```

校验器 `verifyExplanation`：CJK 判废 / 超过 20 词判废 / 复用原词（按词干比对）判废 / 超纲词超过 1 个判废；不合格带原因重试，最多 3 次。

### 评测基线

`npm run selftest`：54 项通过（其中下钻相关 13 项）。

### 待观察

- [ ] 解释是否真的比原词更容易，还是换了个难的词继续绕
- [ ] 单词级缓存导致的多义词误用，实际影响多大
- [ ] 平均下钻深度（如果普遍超过 3 层，说明主流程的简化还不够）

## v1 — 2026-09-14

- 文件：`src/lib/prompt.ts`
- 模型：`deepseek-chat`
- 结果结构：`SCHEMA_VERSION = 'v2'`（新增 `keyWords` / `keyPhrases`，取代 `glossary`）

### 相对 v0 的变化

1. 新增 EXTRACTION 段：要求抽 3~6 个 `keyWords` 与 1~4 个 `keyPhrases`，都用简单英文解释（不超过 8 词）
2. 明确"输入是一个长句时，拆成 2~4 个短句"
3. user prompt 由 `Rewrite this paragraph` 改为 `Rewrite this part`，因为现在也处理选中的句子

### 输出格式

```json
{"simplified": "...", "keyWords": [{"term": "...", "simple": "..."}], "keyPhrases": [{"term": "...", "simple": "..."}]}
```

`parseResult` 会做归一化：单词进 `keyWords`，多词进 `keyPhrases`，并兼容旧的 `glossary` 字段。

### 评测基线

`npm run selftest`：26 项通过。

## v0 — 2026-09-14

- 文件：`src/lib/prompt.ts`
- 模型：`deepseek-chat`
- 温度：0.2
- 结构化：`response_format: { type: 'json_object' }`

### 目标

把英语段落改写成 CEFR 指定级别的英语，保留全部事实，不出现中文。

### 核心约束（system prompt）

1. 只输出英语，绝不翻译，绝不输出中文或其他语言
2. 保留所有事实、数字、人名、日期与逻辑关系，不增不减
3. 尽可能只用最高频的 2000 英语词
4. 每句最多 14 词，一句一个意思，优先主动语态
5. 习语、短语动词、名词化改写为简单动词
6. 专有名词、产品名、无法替换的术语保留原样
7. 无法替换的难词保留，并用括号给出简单英语解释
8. 段落数量与顺序不变

### 输出格式

```json
{"simplified": "...", "glossary": [{"term": "...", "simple": "..."}]}
```

### 评测基线

`npm run selftest`：20 例检查通过（CJK 检测、JSON 解析、词形还原、专有名词、好样例通过、5 类反例被拒）。

### 待观察

- [ ] 真实网页 20 段人工评估：可懂度、事实保真、是否出现中文
- [ ] 平均重试次数与 token 成本
- [ ] A2 / B1 / B2 三档的输出差异是否明显
